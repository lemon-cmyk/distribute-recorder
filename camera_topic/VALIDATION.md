# 验证与来源

更新：2026-11-09。已在 G200 四号机部署：x86 Ubuntu 22.04 / ROS Humble、Thor Ubuntu 24.04 / ROS Jazzy，Domain 14，机内千兆有线连接。

## 实机已验证

- 安装模式：编译随包 Orbbec ROS/SDK 2.9.3，APT 安装 RealSense ROS 4.58.4 / librealsense 2.58.4；驱动加载和三台 USB3 相机启流成功。
- 复用模式：完成驱动安装后，用已有工作空间重新部署，成功启动三台相机，不再次安装依赖或编译。
- 左右 D405 由用户根据抓图确认后绑定真实 Serial Number；没有依据 USB 端口猜测。
- 发布端、root 订阅端和普通用户订阅端生成的 XML，已由目标设备实际 Fast DDS 运行库加载。
- x86 的 root、grg 同时接收六路图像，分别测量 30 秒，均约 29.9～30 Hz；图像均为 640×480。
- Thor 的 root、grg 同时接收三路彩色，分别测量 30 秒，均约 29.8～30 Hz；深度分组的实测结果见四号机部署记录。
- Thor 内部网卡在上述分组测试中无新增 rx_errors；抓包看到 x86 经机内有线网口发送大 UDP 包，Wi-Fi 未捕获同一过滤条件的数据包。
- 相机运行时，订阅环境仍可发现 `/arm/status`、`/body_control/status` 等控制话题。本次没有运行机器人动作，也未验证自定义控制消息的反序列化。
- `orbbec-camera.service`、`realsense-dual.service` 已 enabled 且 active；缓冲服务 enabled 且 active(exited)。未重启整机，尚未做断电冷启动验收。

六路原始图像同时跨机：测量期间未收到完整帧，出现大量 IP 重组失败；六路理论有效负载约 1.106 Gbps，超过当前千兆链路。用户已确认这是预期带宽限制。本包仍配置全部六路，保留 640×480 / 30 fps，没有裁掉深度或降低帧率。三路彩色、三路深度的分组测试不等于六路同时达标。

这些是短时验证，不代表长期稳定性已验收，也不代表其他设备上 Gemini 2 偶发降到 15 Hz 的原因已经解决。

## 本次部署修复

1. APT 仓库未提供独立 `ros-humble-librealsense2-tools` 时，使用主 SDK 的工具，不让整个部署失败。
2. 软件安装遇到后台更新占用锁时，最多等待 180 秒；不删除锁、不结束更新进程。此次实际遇到锁后采用已安装驱动的复用模式完成部署。
3. 发布端显式补全 `metatrafficUnicastLocatorList`。原配置下组件容器未加载相机；补全有线及回环单播发现地址后成功加载并启流。保留 SHM 自动数据地址。
4. 支持 `--head-only`，可在左右尚未确认时先部署头部；填好序列号后恢复普通部署即可启用腕部。四号机最终使用三台完整部署。

## 本地验证

19 项离线测试通过，涵盖复用模式无 APT/编译/udev 操作、工作空间路径与 ROS 版本检查、启动参数兼容性、服务占用检查、source 入口、可选工具包、仅头部模式，以及发布端单播发现配置。执行：

```bash
python3 scripts/test_reuse.py
```

这些测试使用替身模拟 ROS/APT/systemd；实机结论来自上面的远程部署和订阅测量。另做 Bash/Python 语法、JSON、XML 结构、源码 SHA-256 和文档链接检查。上游 2.6.11 XSD 存在未定义类型，不把该 XSD 结果作为兼容性验收依据。
